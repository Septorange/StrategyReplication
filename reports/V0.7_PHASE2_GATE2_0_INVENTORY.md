## Decision

Gate 2.0 inventory is complete. The repository already contains a real V6 Phase3B experiment path for `target_vol`, `haircut`, `midmonth_threshold`, `vt_window`, `quantile`, and commodity cost. It is not yet an experiment library: the API only runs one request, cache identity is an internal directory key, there is no run/evaluation/saved-plan identity or SQLite catalog, browser state holds the last result only, and comparison is hard-coded to the formal V6 baseline. The Mode B page explicitly blocks every non-formal data snapshot. These are the Phase 2.1–2.4 implementation gaps.

No code or data changes were made during this inventory. No network, iFinD, or market-data download was used.

## Existing engine and capability evidence

`backend/parameter_registry.py` exposes the seven original parameters. The only READY original controls are `haircut`, `midmonth_threshold`, and `target_vol`; P1–P4 remain disabled with Phase3A/upstream explanations. Advanced READY parameters include `vt_window` values 60/120/240, `quantile`, and `commodity_cost_bps` values 0/2/5/10. `quantile_lookback` remains disabled at the frozen 240-day value.

`backend/experiment_runner.py` rejects unsupported parameter changes, fingerprints configuration plus adapter/engine/input hashes and the formal baseline, and writes each real execution beneath `experiment_cache/<hash>/`. A cache hit returns `result.json`. The output includes source hashes, a real-engine stage record, daily history, exposure, drawdown, cost and stage artifacts. The key identity is a 16-character config hash; there are no separately persisted run, evaluation-window, or saved-scheme IDs and no SQLite catalog.

`scripts/run_v6_experiment.py` calls these frozen V6 functions: `build_single_asset_vol_control`, `build_execution`, and `build_portfolio_daily`. It preserves full prehistory for prior-only 10VT, then slices and rebases NAV to the formal window. Commodity bps are overlaid on Phase2 roll costs and also passed into Phase3B for portfolio rebalancing costs. Its result labels the experiment real (`synthetic: false`) and marks the response adapter as pending independent audit.

## Current Mode B limitations

- `POST /api/experiment` returns a result directly; there are no `run`, `evaluate`, `save`, `list`, `open`, or pairwise `compare` routes.
- The request schema has no snapshot/evaluation identity. Runner fingerprints use the one formal summary supplied at startup.
- Results are not discoverable after restart from an application catalog; a browser reload loses `state.experimentResult`.
- UI comparison is experiment versus baseline V6 only, not arbitrary saved scheme A versus scheme B.
- The current experiment route always forces formal scope in middleware, so an extended snapshot cannot run against its own complete dates/data even though published extension data exists.
- Current cache output includes full run artifacts but does not register a durable user-visible saved scheme, evaluation slice, or comparison lineage.

## Gate 2.1–2.4 implementation contract

1. Permit only READY parameters through a strict capability check. Preserve disabled original P1–P4 behavior and the supported advanced parameter allowlists.
2. Run the real Python engine against the selected supported snapshot/evaluation input, with snapshot-specific source identity. At minimum, run `target_vol=12%` and commodity cost `5bps`; the latter must retain both roll and rebalance cost effects.
3. Persist distinct run/evaluation/saved scheme identity and full artifact references in an SQLite catalog while keeping complete artifacts on disk. A restart must reopen the saved extended-snapshot 12%/5bps scheme without rerunning.
4. Compare any two saved schemes on an explicitly resolved common interval and return paired path/KPIs/costs with each scheme's own snapshot and parameter identity.
5. Expose the lifecycle in Mode B (run, evaluate, save, library list/open, and two-scheme comparison), including useful diagnostics for stale/missing artifacts.
