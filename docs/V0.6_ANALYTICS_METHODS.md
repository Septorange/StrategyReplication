# V0.6 analytics methods

The source is the frozen V6 formal evaluation window 2015-09-30–2024-11-20 (2,220 observations). The visualization and experiment-response layer is newly developed and pending independent audit. Frozen V6 and V0.5.1 are read-only.

Canonical `data/v6_web/daily_portfolio.parquet` and `daily_asset_state.parquet` contain full precision derived from frozen V6 outputs. Export with the V6-compatible arm64 `.venv` to `data/v6_analytics`; the web runtime reads JSON written with full IEEE754 float precision. Older V0.5.1 web JSONL rounded floats to 10 decimal places and is unsuitable for the required 1e-10 metric reconciliation. No old reference CSV or PNG supplies historical results.

1. History uses the saved formal V6 net and gross NAV, already rebased from the common evaluation-window high water 1. Independent `(1+r_net).cumprod()` agrees. The first trading day's saved NAV includes that day's return; it is not overwritten with 1. The display series is inclusive `rolling(window,min_periods=window).std(ddof=1)*sqrt(252)` on formal net daily returns; at 120D, observations 0–118 remain null. This is distinct from the strategy's prior-only pre-10VT estimator. Date filtering occurs after rolling calculation.
2. Performance uses daily mean / sample standard deviation × sqrt(252) for Sharpe, with zero risk-free rate. Full-period displayed return uses `annualized_return = final_nav**(252/n)-1`; each calendar-year displayed return uses compounded interval return. The separate `return` field remains compound interval return even for the full period. Annualized volatility uses sample standard deviation. Annual MDD includes an initial high water of 1 in each year's subseries. 2015 and 2024 are partial years; their start/end and observation count accompany the data. Source V6 annual CSV is not reused because annual interval semantics are computed explicitly.
3. Win rates default to overlapping `NAV[t+h]/NAV[t]-1`, for every t with t+h available: exactly 2,220−h windows. No extra NAV=1 observation is inserted. Positive and negative returns determine the win-rate denominator; zeros and nonfinite values are counted separately. Average loss is null when there are no negative observations. Optional nonoverlap uses starts 0,h,2h,… and a distinct method id. Neither is predictive accuracy.
4. Class contributions are sums of the daily net asset-contribution series, grouped by calendar year and class. API values are return fractions; display `100*value` as percentage points (pp). These arithmetic sums do not equal compound annual NAV returns. V6 asset contribution already subtracts each asset's allocated contract-roll and portfolio-rebalance costs; do not subtract them twice.
5. Eleven asset rows per year use the same net contributions and class mapping. `NOT_LISTED_OR_NOT_ELIGIBLE` has null contribution when no actual eligible trading sample exists; `NOT_PARTICIPATING` has genuine zero contribution when eligible but no start-of-day holdings exist; `PARTICIPATED` includes real contributions even if their total happens to be zero. Missing held-return contributions are null with `MISSING_HELD_RETURN`. Eligibility is not inferred from returns or a manually coded IPO date.
6. Nominal exposures sum `weight_start_of_day` by date and class. Bond exposure may exceed 1x. Dashed volatility uses the class daily contribution sum, then the same rolling sample standard deviation. It is not class market-return volatility and is not RC. Filters change views only.
7–8. Drawdown episodes share one event table. Initial high water is 1; the latest attained high-water date becomes peak, minimum NAV/high-water−1 becomes trough, and first NAV >= peak high-water becomes recovery. Rank by ascending signed drawdown. Risk accumulation is peak→trough; recovery is separate. Durations are trading-index differences, not calendar days. Unrecovered episodes retain null recovery date/duration. Top5 display, table and experimental drawdowns use this implementation.

Every endpoint returns strategy version, formal window, versioned method id, units, REAL_V6_DERIVED status, display window and analytics manifest SHA256. Nulls remain JSON null, never NaN/Infinity. Advanced display windows recompute display statistics using the saved full-window daily input; they never change holdings.

Mode B invokes immutable `src/phase3b.py` functions with full phase2 return prehistory and frozen phase3a base targets. `haircut`, `quantile`, `midmonth_threshold`, `target_vol`, allowed vt windows and both commodity-cost layers are overridden only in independent memory/output. P1–P4 and quantile_lookback remain baseline-only with explicit DISABLED responses for changed requests. Frozen Phase3A cannot be reused for changed momentum/risk-budget definitions. Formal experimental NAV is recomputed on the common formal window after retaining causal prehistory for execution; old audited rebasing and cost-scope fixes are preserved. Cache identities hash adapter code, engine code/config, real inputs and baseline. Results include actual params, param differences, stage artifacts, costs, exposures, NAV and drawdowns.

Reproducible validation commands from the V0.6 project directory:

```sh
/usr/bin/arch -arm64 ../.venv/bin/python scripts/export_v6_analytics_snapshot.py
/usr/bin/arch -arm64 ../.venv/bin/python scripts/validate_v6_analytics.py
/usr/bin/arch -arm64 ../.venv/bin/python scripts/validate_v06_experiments.py
/opt/anaconda3/bin/python -m pytest tests/test_analytics.py tests/test_real_experiment_evidence.py tests/test_experiment.py tests/test_experiment_costs.py
```

The first command writes only V0.6 independent snapshots/reports. The frozen input directories are read-only. Real experiment cache directories retain prior adapter fingerprints for traceability; serving uses only the current identity, and evidence tests compare every source hash to the current files. Original seven-parameter number3 is canonically `short_vol_windows=[20,60]`; `asset_short_vol_window` is a compatibility request alias that accepts only20 and cannot change the actual max(20,60) method.
